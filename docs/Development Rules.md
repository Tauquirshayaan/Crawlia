Development Rules

• Read every attached markdown file before making changes.
• Never overwrite existing working functionality.
• Preserve backward compatibility.
• Search the entire project before creating duplicate code.
• Reuse existing components whenever possible.
• Follow the documented architecture exactly.
• Keep code modular and feature-based.
• Do not leave placeholder implementations.
• Do not introduce breaking changes without documenting them.
• Update documentation whenever code changes.
• Keep database migrations reversible.
• Keep APIs versioned where appropriate.
• Ensure all new code passes linting and tests.
• Optimize for readability, maintainability, and scalability.
• If uncertain, ask for clarification rather than making assumptions.
